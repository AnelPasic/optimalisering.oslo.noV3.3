## Exact implementation

1. **One canonical source array in `home.json`:** migrate all current placements in source-render order `topSections` then `sections` then `bottomSections` into **one `sections` array**. Preserve the **FULL, byte-semantically identical payload of every placement** (type, UUID, local ID/name/body/items/links, surface/visibility, global reference, order). Do not silently delete a `hidden` row because it isn't public. Keep `forbehovsvelger` first and `behov` second *at migration time if still current*. Drop obsolete `topSections` and `bottomSections` keys from this page only **after** correct merge. Do not change the global master files.
2. **One native Pages CMS list** under `Forside → Innholdsseksjoner` immediately after the grouped Hero: `type: block`, `blockKey: _block`, same existing choices **«Globalt element»** and **«Innholdsseksjon»**, same field models and visibility controls, freely movable/reorderable/hidden/deletable placements. Set an adequate max (up to 56, matching existing homepage validated total) rather than silently capping at old Main=24. Remove separate `Valgfrie seksjoner Topp`, `Hovedseksjoner`, `Valgfrie seksjoner Bunn` controls. Keep existing responsive rendering, design primitives and named authoring fields; no new shadow registry, placement order keys or cloned global content.
3. **Simplify schema/resolvers for real:** `homepageSourceSchema`, `resolveHomepageSections`, `getHomepageBlocks`, `pageSchema` and public-link/anchor validations must consume the new **single canonical `sections`** as the persisted shape. Retire obsolete three-area runtime branching/schema only when all project call sites/tests/fixtures are migrated. At the migration boundary explicitly REJECT leftover `topSections/bottomSections` nonempty data or stale CMS saves instead of silently dropping it; failure must have a readable message. No unnecessary long-lived fallback or parallel old/new editor sources. Reuse the already approved native same-list architecture: fixed Hero + typed one ordered list + global master references. Extract a small shared primitive/helper with Synlighet if clearly a **net reduction** in code, but avoid widening service-page scope or creating a generic builder framework.
4. **No ghost sections:** for homepage, public content sections must correspond one-to-one with **visible CMS placements**, in their stored order, after the fixed Hero. Hidden CMS rows remain saved/reversible, not rendered. Existing global packages/proof/assessment/FAQ fetch their **content from the eight canonical master records**, never copied to local page. Site shell/header/footer and components *within* a selected block (e.g. Hero contextual microproof if legitimately selected) are not additional separate CMS section entries. Never auto-insert global alternatives when a row is removed/hidden.
5. **Preservation:** do not change existing homepage H1, CTA URLs, graphic/crop, approved packages/prices, proof media/evidence/permissions, eight global UUIDs, `homepage.chrome`, SEO/robots, local OWNER section fields, local images, current B/commercial content, or any other page. Do not use old saved snapshots to overwrite the recent real `behov` placement. Keep protected #sjekk/#priser and every relevant local/public fragment-link guard. Singleton and duplicate master prevention must still hold (including hidden references). The current Synlighet hub and its OWNER calculator must remain intact; do **not** modify `/synlighet/` page content.
6. **CMS editor ordering:** Hero first; then just **«Innholdsseksjoner»**; other SEO/site-shell fields can remain as their logically named controls. The editor should not show old Topp/Hoved/Bunn categories in parallel or duplicate a global master's editable source.
