# Visual Production Model — v3.3

## Why

v3.2 correctly learned that changing typography, palette, geometry, components, imagery and copy at once makes feedback useless. The failure was turning every visual layer into an owner micro-gate.

v3.3 keeps controlled experiments but changes the approval granularity.

## Preconditions

Before serious visual styling, have:
- page role and search intent;
- complete/near-final content for the representative page;
- proof availability/limits;
- CRO/information hierarchy;
- primary conversion path.

## Three-stage visual flow

### A. Visual brief

Produce one concise brief:
- desired character;
- useful reference principles;
- anti-patterns;
- existing brand constraints;
- mobile/density requirements;
- media reality.

If materially different visual identities are still plausible, show at most 2–3 controlled directions and obtain one owner choice.

### B. Internal system resolution

Resolve in controlled order:
1. typography;
2. palette/distribution;
3. geometry/layout;
4. component language;
5. imagery/explanatory visuals;
6. density/rhythm.

Use same approved content and one-variable comparisons when uncertainty exists.

**These are not automatically owner gates.** The design agent should choose routine details consistent with the approved visual brief. Escalate only when alternatives create meaningfully different brand outcomes.

### C. Representative full-page gate

Build one realistic full page before scaling the site.
Review desktop + mobile:
- hierarchy;
- visual life vs noise;
- whitespace;
- color distribution;
- repetition/cardification;
- proof visibility;
- decision-section clarity;
- long Norwegian copy fit;
- rhythm across the complete scroll.

Owner approval here locks the visual system for scale.

## Diagnostic revision rule

When feedback is “too boring”, “too corporate”, “too aggressive”, “too white”, etc.:
1. identify likely failing layer;
2. state what remains locked;
3. change the smallest coherent layer;
4. compare against previous state.

Do not respond with a total redesign unless a reset is explicitly approved.

## Anti-patterns

- multiple full-page variants where every variable changes;
- moodboards detached from real project content;
- cards as default paragraph wrappers;
- color added everywhere to compensate for weak hierarchy;
- design dependent on media that does not exist;
- design agent rewriting content to make the layout easier;
- owner approval on spacing pixels and trivial responsive fit.
