# Design Direction

Use the current Medon design/CRO reference as the detailed source.

This file defines the Medon Web System v3 process.

## Before coding

If an established brand exists:
- use its real brand guide/assets.

If not:
- propose 2–3 credible directions;
- recommend one;
- explain why it fits the audience and offer.

Do not let the framework/theme determine the brand.

## Direction must define

- visual tone;
- typography strategy;
- color roles;
- container/grid feel;
- image direction;
- card/surface language;
- radius/shadow level;
- motion level;
- primary CTA treatment;
- trust/proof presentation;
- desktop/mobile behavior.

## Norwegian/Nordic credibility filter

Default toward:
- clarity;
- restraint;
- strong typography;
- generous whitespace;
- real proof;
- simple interaction;
- low gimmick density.

Avoid generic “AI SaaS purple” or trend cloning unless the brand/market genuinely calls for it.

## Design is not copy

Do not compensate for a weak offer/hook with animation, gradients or decorative complexity.


## Decision discipline

This file defines what must be decided, but the approval sequence lives in `DESIGN-DECISION-WORKFLOW.md`.

Do not collapse typography, palette, layout, component style and imagery into three unrelated full-page “directions”. Compare one major variable at a time using the same message and structure.

Every approved visual decision must be recorded in `DESIGN-DECISIONS.md`.
