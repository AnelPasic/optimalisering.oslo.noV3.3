# Design Decision Workflow — v3.3

This file is the detailed execution companion to `VISUAL-PRODUCTION-MODEL.md`.

## Core rules
1. Preserve approved content/IA while judging visual variables.
2. Change one major variable at a time when comparison is needed.
3. Use real project content and browser-rendered desktop + mobile.
4. Do not ask the owner to approve routine design mechanics.
5. Escalate materially different brand directions.
6. Lock the system at the representative full-page gate before site-wide scale.

## Stage 0 — prerequisites
Need page role, conversion path, near-final content, proof reality and grayscale hierarchy. Design expresses the argument; it does not invent it.

## Stage 1 — visual brief / character
Normalize references into principles: typography character, color distribution, spacing/rhythm, hero/nav, open vs carded structure, imagery, anti-patterns. If multiple materially different identities remain, show at most three and recommend one.

## Stage 2 — controlled system resolution
Resolve internally in order:
- typography;
- palette/distribution;
- geometry/layout;
- component language;
- imagery/explanatory visuals;
- density/rhythm.

When uncertain, create bounded same-content specimens. Preserve all other variables. Record meaningful decisions; do not create owner bureaucracy for micro-values.

## Stage 3 — representative full page
Use the page with broadest real section variety. Show full desktop + mobile. Review hierarchy, repetition, proof, CTA recurrence, card density, whitespace, color frequency, long-copy readability and complete-scroll rhythm.

Owner approval here makes the system authoritative.

## Stage 4 — family scale
Implement one example of each materially different page family before mass production. Use template canary for scaled publishing.

## Revision protocol
Feedback such as “boring”, “too corporate”, “too aggressive”, “too white” must be diagnosed. State:
- likely failing variable;
- what remains locked;
- exact variable changed;
- comparison result.

Do not answer vague feedback with an uncontrolled full redesign.

## Stop-loss
After 2–3 failed controlled attempts, reopen the prior assumption. Do not generate endless variants.
