# START-EXISTING-PROJECT — v3.3

## Package rule
Medon Web System v3.3 is self-contained.

## Read first
`AGENTS.md` → `BLUEPRINT.md` → `WORKFLOW-v3.3.md` → Role Ownership → existing-site modernization → current project truth → only routed references.

## Do not migrate by default
A functioning site is not rewritten because the starter prefers newer tooling. Migration requires a business/maintenance case.

## Audit labels
`KEEP` · `FIX` · `TEST` · `MISSING` · `UNKNOWN`.

## Audit order
business constraint → conversion/measurement → offer/message/proof → real funnel/query evidence → technical/crawl/indexation → content footprint → mobile/functional UX → architecture/maintenance.

For material CRO work diagnose the leak before redesign.

## Content ownership
Existing proven copy is evidence. Do not let a fresh implementation agent casually rewrite it. Route material copy/positioning changes through Strategy/Content and compare against baseline.

## Design ownership
Preserve proven layout/brand behaviors unless evidence or explicit brief justifies change. For redesigns use the Visual Production Model and representative page before scale.

## Implementation
Implement the smallest coherent high-value batch. Preserve valuable URLs, redirects, analytics, forms, conversion history, proven proof/copy, identity and canonical domain.

## Migration from older Medon workflow
Use `templates/PROJECT-MIGRATION-AUDIT.md`. Import validated knowledge, not historical conversation clutter. Copy seeds are not locks.

## First response
Return diagnosis, KEEP/FIX/TEST/MISSING/UNKNOWN, strongest opportunity, biggest risk, smallest coherent batch, and whether migration is justified.
