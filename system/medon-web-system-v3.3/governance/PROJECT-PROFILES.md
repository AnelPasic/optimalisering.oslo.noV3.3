# Project Workflow Profiles

The system must be rigorous without becoming bureaucratic. Select the lightest workflow that matches project risk and complexity.

## FAST

Use for:
- campaign sites;
- Medon-owned microsites;
- roughly 1–10 substantive pages;
- simple offers;
- low editorial complexity.

Required path:

```text
Technical Preflight
→ Commercial/Search Lock
→ Complete Content
→ CRO/IA
→ Visual System + Representative Page
→ Implementation
→ QA/Launch
```

Skip deep reputation mapping, canary systems and broad content operations unless the project actually needs them.

## STANDARD

Default for normal SMB websites:
- roughly 5–100 pages;
- Astro + Pages/Sanity/static;
- SEO/AIO + lead generation;
- service pages, cases, articles, FAQs.

Use the full v3.3 production path and routed research/QA. Owner approval is required only for material decisions.

## ADVANCED

Use when one or more materially apply:
- multilocation;
- programmatic/scaled content;
- substantial existing search footprint;
- high paid-media spend;
- complex funnels;
- many entities/content relationships;
- serious reputation/YMYL sensitivity;
- multiple languages;
- large proof/data library.

Add, where relevant:
- independent reputation research;
- GSC/GBP/query data;
- retrieval/source ecosystem mapping;
- content footprint audit;
- template health/canary rollout;
- deeper CRO evidence triangulation;
- distribution/source graph;
- experiment tracking.

## EXISTING_SITE

Do not use greenfield assumptions.

Start:

```text
baseline
→ content/search footprint
→ funnel leak diagnosis
→ KEEP / FIX / TEST / MISSING / UNKNOWN
→ smallest evidence-backed improvement batch
```

Do not redesign what has not been diagnosed.

## Selection rule

The agent must recommend one profile and explain why in 3–6 lines. If requirements later cross a real threshold, raise a change request; do not silently upgrade complexity.
