# SEO / AIO Skill v3.3

## Core rule

**Research first. Write second. Generic consensus content is trash.**

A keyword is not a brief. A page must solve an actual job and add useful information beyond both competitors and the site's own existing pages.

## Before writing

Establish:
- query/search intent;
- buyer awareness;
- SERP format/features;
- business entity and real service/location scope;
- existing-site overlap;
- competitor consensus;
- first-party/customer evidence;
- missing angle/information gain;
- conversion goal;
- proof available and proof missing.

For important AI-search topics also map:
- whether AI answers/overviews are present;
- cited/source domains and source types;
- recurring entities/facts;
- likely fan-out subqueries, comparisons and follow-ups.

Use fan-out to improve coverage, not to create one URL per subquery.

## Research order

Prefer:

```text
verified business facts
→ GSC / GBP / analytics / CRM / calls / emails / reviews
→ current site
→ authoritative primary sources
→ live SERP / competitors
→ relevant communities/forums
→ model inference
```

Research competitors to identify consensus and gaps, not to remix their copy.

## Page Existence Test

Before creating a service/local/comparison/programmatic page ask:

> What would actually be missing if this page did not exist?

Valid value can include:
- own experience;
- real customer questions;
- first-party data;
- actual local/operational constraints;
- cases/results;
- concrete pricing/process/requirements;
- original analysis/comparison;
- useful tool/calculator/assessment.

City/keyword/synonym swaps do not count.

## Same-site redundancy

Compare with existing pages before creating another URL.

Allowed outcome:
- improve existing;
- merge;
- redirect;
- canonicalize where technically appropriate;
- do not publish.

## Local SEO

Mirror the real business, not a keyword matrix.

- real physical location ≠ service area;
- GBP categories/services and website should be coherently aligned;
- location pages need real business × service × place value;
- service-area pages must earn the URL;
- real reviews, photos, team, process and reputation matter more than geo-tag tricks.

## Entity clarity

Make clear:
- who the business is;
- what it provides;
- where;
- for whom;
- with what proof;
- what action follows.

Use consistent names/categories/locations and valid structured data where relevant.

## AIO / answer extraction

Make useful answers easy to extract:
1. answer/direct statement;
2. nuance;
3. evidence;
4. decision rule/trade-off;
5. next step.

Do not bury the answer in branding fluff.

Build truthful corroboration across relevant owned/earned platforms. Never fabricate consensus, awards, reviews or community mentions.

## Needs Met vs quality

Evaluate separately:
- page quality: effort/originality/skill/accuracy/credibility;
- needs met: does the page actually solve the searcher's job?

If a calculator, assessment, configurator or comparison tool solves the job better than an article, consider that instead.

## Hooks / conversion layer

After research and angle selection, generate multiple hooks.

A hook must pass:
- no delay — topic clear immediately;
- no confusion;
- no irrelevance;
- no empty curiosity.

Useful optional formulas:
- how to [yay] without [boo], even if [fear];
- common belief → deeper issue;
- buyer mistake → better decision rule;
- damaging admission → credible benefit;
- specific painful moment → root cause;
- fit / not-fit disqualifier;
- proof-before-promise.

These are tools, not compulsory templates.

## Proof

Proof beats promise.

Prefer:
- verified first-party results/data;
- documented cases;
- real customer language;
- concrete process detail;
- actual photos/video;
- current credentials/partnerships;
- transparent limitations.

Never invent results, ratings, testimonials, clients, certification, scarcity, guarantees or current platform facts.

## Facts / insights

For Medon-owned topical sites, actively identify sourced facts that improve understanding/decision usefulness. Use `content/fun-facts.md` and record date/scope/volatility.

External market facts give context; they do not prove client-specific performance.

## Scaled content

Before large-scale production:
- test representative pages first;
- track indexation/performance by template;
- compare semantic similarity;
- stop the line if template health degrades;
- improve/consolidate/remove rather than blindly generate more.

Indexation is a QA signal, not a business KPI.

## Technical baseline

Verify as relevant:
- indexability;
- canonical/redirects;
- sitemap/robots;
- internal links;
- rendering/crawlability;
- Core Web Vitals/performance;
- mobile/accessibility;
- image optimization;
- structured data validity.

Do not let a technical checklist distract from a larger content/entity/offer problem.
