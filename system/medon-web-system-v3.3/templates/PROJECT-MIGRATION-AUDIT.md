# Project Migration Audit

Use when moving a project from an older workflow into a new system. Do not import historical clutter as operating truth.

## KEEP
Validated facts/decisions/assets worth carrying forward.

## REVIEW
Potentially useful decisions that need revalidation.

## DISCARD
Rejected, weak, contradictory or process-generated artifacts that should not constrain the new project.

## MISSING
Required facts/content/proof/technical inputs not yet available.

## COPY SEEDS
Promising wording only. Not authoritative production copy until the new content process locks it.

## DESIGN PRIORS
Useful visual lessons. Distinguish strong priors from immutable brand rules.

## TECHNICAL BASELINE
Known-good architecture/integrations/deployment/measurement decisions.

## FRESH-SESSION HANDOFF
Concise instructions an implementation agent can read without historical conversation context.
