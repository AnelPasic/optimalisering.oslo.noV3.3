# Proof Router

Proof is part of persuasion architecture, not a footer decoration.

## Site ownership gate

```text
MEDON_OWNED
→ Medon Proof Library MAY be routed when relevant and publication-approved.

CLIENT_OWNED
→ Medon Proof Library is DISABLED.
→ only client-owned/approved evidence may support client claims.
```

Do not even use a Medon result as inspiration for a client performance claim.

## Match proof by

- claim;
- buyer objection/doubt;
- service;
- audience/segment;
- funnel stage;
- Value Equation role;
- context/geography where material;
- publication permission.

## Proof strength

Use as an internal ordering aid:

- Level 5 — verified before/after result with provenance/context;
- Level 4 — documented case with result and intervention;
- Level 3 — verified first-party data/experience;
- Level 2 — permissioned testimonial/review;
- Level 1 — process/capability/experience evidence;
- Level 0 — unsupported claim.

A Level 1 proof item cannot justify a Level 5-style result promise.

## Claim → doubt → proof → placement

For every material claim:

```text
CLAIM:
BUYER DOUBT:
VALUE EQUATION ROLE:
AVAILABLE PROOF:
STRENGTH:
SOURCE:
PUBLICATION STATUS:
BEST PLACEMENT:
```

Place proof near the doubt it resolves.

## Publication states

Use separate states where possible:
- evidence status;
- wording/review status;
- permission status.

Only publication-approved combinations may ship publicly.

Development placeholders must be explicitly labelled and omitted from release builds.
